# 仓管家 · 本地仓库管理

CangGuanJia / StockKeeper —— 一个跑在自己电脑上的小型仓库、库存管理工具。
数据存在本地的 SQLite 文件里，不需要联网、不需要装数据库服务、不需要注册账号。

## 三种用法

### 1. 双击 exe（最简单）

桌面上的 **`仓管家.exe`** 就是程序本体，双击后：

1. 静默启动本地服务（**没有黑色命令行窗口**）
2. 自动打开浏览器进入 <http://localhost:3333>
3. 右下角系统托盘出现一个纸箱图标，并弹出一次提示

**托盘图标怎么用**

| 操作 | 效果 |
| --- | --- |
| 双击图标 | 打开管理界面 |
| 右键 → 打开仓管家 | 打开管理界面 |
| 右键 → 打开数据文件夹 | 在资源管理器里定位数据库 |
| 右键 → 退出仓管家 | 停止服务并退出 |

关掉浏览器不影响程序运行，服务一直在；想彻底退出就用托盘的「退出仓管家」。
重复双击 exe 不会启动第二份，只会把界面打开。

- 数据位置：`%LOCALAPPDATA%\仓管家\data\warehouse.db`
- 日志位置：`%LOCALAPPDATA%\仓管家\logs\app.log`（没有黑窗口，出问题看这个文件）
- 图标缓存：`%LOCALAPPDATA%\仓管家\cache\tray.ico`

### 2. 双击 `启动.bat`（源码方式）

需要电脑上装了 Node.js。会自动完成「装依赖 → 构建页面 → 启动服务 → 打开浏览器」。

### 3. 命令行

```bash
npm install      # 只需第一次
npm start        # 构建 + 启动
npm run dev      # 开发模式：后端 3333 + 前端热更新 5173
```

## 重新打包 exe

改了代码后想更新桌面上的 exe：

```bash
npm run build:exe
```

产物在 `release/仓管家.exe`，复制到桌面即可覆盖旧版本。
只改图标的话单独跑 `npm run icon`。

打包用到的东西：

- **Node SEA** —— 官方的单文件可执行方案，底座就是 node.exe
- **esbuild** —— 把整个服务端打成一个 CJS 文件
- **resedit** —— 把图标和版本信息写进 exe（纯 JS，不需要额外工具）
- **PE 子系统补丁** —— 把 exe 从「控制台程序」改成「GUI 程序」，双击才不会有黑窗口
- **前端资源 + 托盘图标** 以 base64 内嵌进 exe，所以 exe 是自包含的，不依赖 dist 目录

系统托盘没有用任何原生模块：启动一个隐藏的 PowerShell 进程创建 `NotifyIcon`，
菜单点击通过标准输出回传命令给 Node，Node 再执行对应动作。
父进程退出时，托盘进程会自己检测到并退出，不会留下点不掉的幽灵图标。

## 功能

| 页面 | 能做什么 |
| --- | --- |
| 库存概览 | 库存总额、总数量、低库存预警、分类金额分布、占用金额最多的商品、最近出入库动态 |
| 商品档案 | 商品的增 / 删 / 改 / 查，按名称、编号、规格、位置搜索，按分类筛选，只看预警 |
| 入库记录 | 同一个商品按不同单价分批入库，自动重算平均价 |
| 出库记录 | 记录领用、消耗、发货，库存自动扣减 |
| 数据管理 | 导出 Excel、下载导入模板、导入 Excel、载入示例数据、清空数据 |

商品详情里可以看到每个商品的**全部采购批次**，以及采购价区间。

## 平均价怎么算的

一个商品可能分好几次、按不同价格买入，系统同时给出两个口径：

- **加权平均价 = 总金额 ÷ 总数量**
  例：买 2 个 @10 元 + 10 个 @12 元 → (20 + 120) ÷ 12 = **11.67 元**
  买得多的批次权重更大，最贴近真实成本。**库存金额 = 当前库存 × 加权平均价**，界面上的金额都按这个口径。
- **简单平均价 = 各批次单价直接平均**
  上例 = (10 + 12) ÷ 2 = **11 元**
  适合「每批采购量差不多，只关心价格波动」的场景。

界面上两个值都显示，加权价加粗显示，简单价在下方小字。

## 数据存在哪 / 怎么备份

```
app/server/data/warehouse.db     ← 所有数据都在这个文件里
app/server/data/warehouse.db-wal
app/server/data/warehouse.db-shm
```

- **备份**：停掉服务，把整个 `app/server/data` 文件夹复制一份即可。
- **换电脑**：把 `data` 文件夹拷到新机器的同一位置（或直接复制整个 `app` 目录）。
- 服务运行时不要用别的工具直接改这个文件，要看/改数据请用「导出 Excel」。

## Excel 导入导出

**导出**：点「导出全部数据」，得到一个工作簿，含三张表
`商品汇总`（含加权/简单平均价、库存金额）、`入库明细`、`出库明细`。

**导入**：先点「下载导入模板」，按模板的三张表填好再上传：

| 工作表 | 需要的列 |
| --- | --- |
| 商品档案 | 名称（必填）、编号、分类、规格型号、单位、存放位置、预警值、备注 |
| 入库明细 | 商品名称（必填）、编号、规格型号、入库日期、数量（必填）、单价、供应商、备注 |
| 出库明细 | 商品名称（必填）、编号、出库日期、数量（必填）、领用人、备注 |

导入规则：

- 是**追加**不是覆盖。已存在的商品（按编号，其次按名称匹配）会保留原数据，只补空缺字段。
- 商品名没填过的会**自动新建**商品档案。
- 日期支持 `2026-09-30`、`2026/9/30`、Excel 日期格式。
- 工作表名字不必完全一致，叫「商品」「入库」「出库」也能识别。

## 常见问题

**端口被占用？** 换个端口：`set PORT=3456 && npm run serve`。

**改了代码后页面没变？** 生产模式要重新构建：`npm run build`，或者开发模式 `npm run dev` 会自动热更新。

**能同时开多个标签页用吗？** 可以，SQLite 会正确处理并发写入。

**手机上能用吗？** 页面是响应式的，但服务只监听本机，局域网内其他设备访问需要自行处理防火墙与监听地址。
